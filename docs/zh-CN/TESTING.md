# 测试

安装推理/开发依赖，然后运行：

```bash
python -m pip install -e ".[acoustic,vocoder]" -r requirements/development.txt
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
(cd vocoder && python -m pytest -q)
node --test tests/position-lock.test.cjs
```

根目录测试使用真实的基于参考条件的 AdaSpeech 和 BigVGAN 模型、原始符号/前端函数、合成参考输入，以及随机初始化的较小测试检查点，覆盖公开的文本转 WAV CLI。声学时长预测器的测试夹具被设置为已知输出，以便独立检查预期的 token/帧/WAV 长度。测试不使用下载的语音模型或私有语音。

覆盖范围包括：postnet 真实长度裁剪和 CT 顺序；真实文本及多行文件经声学预测和所选声码器的处理；参考梅尔频谱和波形条件输入；模型/配置/参考输入/解释器/设备缺失错误；无效嵌入；路径隔离/相对于调用者目录的路径；防止覆盖任何输入资源；独立的已保存梅尔频谱/WAV 合成约定；数组验证/覆盖处理；以及直接表征波形前端、展示预期填充差异的测试。

声码器测试套件使用真实检查点/WAV/NumPy I/O，单独运行实际的缩小架构。两个显式 Apple MPS 测试用例均已在禁用 CPU 回退的情况下通过本地验证。Linux CI 使用 Python 3.10/3.12；依赖 MPS 硬件的用例会在其中跳过。网站保留了三个针对播放功能的回归测试。新的文本流水线在 CPU 上完成测试；可选的已下载 pyannote 编码器执行、训练检查点质量和完整的声学模型 MPS 支持不在此测试记录范围内。

wheel 冒烟检查会将项目安装到独立的导入目录中，并从检出目录外调用已安装的控制台命令，其中包含实际的文本转 WAV 合成。测试证明可执行数据流和资源打包正常，不证明论文检查点质量、完整训练/恢复流程或检测器指标。精确的本地运行结果和上传校验和保存在维护者的外部交接记录中。

旧检查点回归测试覆盖有限的 NumPy 标量白名单、拒绝任意 pickle 代码、严格状态匹配，以及省略外部统计文件时逐字节恢复不均匀的音高/能量分箱。

本地提供的完整尺寸声学模型及 V/VR/VRT 检查点也通过了严格状态匹配。三次端到端检查使用 CPU 上的完整声学权重、禁用 CPU 回退的 Apple MPS 上的 V、VR 或 VRT、合成的 512 维单位身份向量，以及公开参考 WAV。测试文本产生的同一 CT 梅尔频谱 [80,50] 生成了三个不同的非静音单声道 PCM16 WAV，每个均为 22050 Hz、12800 个采样点。这验证了可执行兼容性，不代表原始说话人条件、语音质量或检测器指标验证。
